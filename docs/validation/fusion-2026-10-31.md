# Provisional camera/radar fusion — 31 October 2026

Implementation: `ground_station/ares/fusion.py` (`fusion-provisional-v1`), run by the backend every 0.5 s
on the laptop. Everything here is **provisional and uncalibrated**: weights, evidence mappings,
thresholds and persistence are engineering defaults for the demo, to be replaced by Phase 5 selection.

## Rules

| Step | Rule |
|---|---|
| Camera evidence | Highest person score in the current detector result; 0 if the detector ran and found nobody; unavailable if there is no current result (camera stale, test pattern, model missing) |
| Radar evidence | 1 if the current radar report has a target (moving or stationary), else 0; unavailable if radar is not streaming/stale or the report is invalid. Raw energy and distance are not used |
| Weights | Operator profile: clear 0.7 camera / 0.3 radar; reduced visibility 0.2 / 0.8. Synthetic IR has weight 0 and is never an input |
| Missing input | Excluded, not treated as 0. Index is renormalised over available sources; **coverage** = share of profile weight present |
| Index | Weighted mean of available evidence. Not a probability (`index_is_probability: false`) |
| Hysteresis | Candidate PRESENT at index ≥ 0.5, ABSENT at ≤ 0.3; between, a settled decision is held |
| Persistence | A decision changes only after the same candidate on 2 consecutive updates (~1 s) |
| Profile change | Restarts persistence history |
| Disagreement | Flagged when available sources differ by ≥ 0.5 |
| Output wording | `POSSIBLE_PERSON`, `NO_PERSON_INDICATED`, `NO_PERSON_INDICATED_PARTIAL_COVERAGE`, `UNCERTAIN`, `INSUFFICIENT_EVIDENCE` |

API: `state.fusion` (index, coverage, contributions, pending candidate, config, profile, cited
`camera_frame_id` and `radar_sequence`, `spatial_alignment: UNVERIFIED`) and `state.assessment`
(`FUSED_PROVISIONAL`, `CAMERA_ONLY_PARTIAL_COVERAGE`, `RADAR_ONLY_PARTIAL_COVERAGE`, or the reason
no fusion exists). `presence_score` stays null. Decision changes are recorded as `fusion_decision`
events; 1 Hz telemetry also carries the fusion state.

## Known consequences of the provisional rules

- **Clear profile, radar target the camera cannot see** (camera 0, radar 1): index 0.3, decision
  `NO_PERSON_INDICATED` with the disagreement flag. In reduced visibility the same evidence gives 0.8,
  `POSSIBLE_PERSON`. This is the intended profile effect, but the clear-profile result can miss a person
  outside the camera's view; the disagreement flag is the operator's cue.
- Radar presence is binary and covers a wider zone than the camera; without scene alignment the two
  sources may describe different areas.
- Fusion runs on its own tick, so it may cite a camera frame up to ~0.5 s older than the newest one.

## Live fusion with the real radar

Main backend restarted on port 8000 with `ARES_CAMERA_URL=http://ares.local/capture`,
`ARES_RADAR_ENABLED=1`, `ARES_RADAR_ADDRESS=08:B6:52:78:9D:46`. The radar reported "not advertising"
for about 15 s while the previous BLE link released, then streamed. Camera READY throughout.

Clear profile, user present near the node (radar `MOVING_AND_STATIONARY`), five 1 s samples:

| Camera evidence | Radar | Index | Decision | Disagreement |
|---|---|---|---|---|
| 0.00 | 1.00 | 0.300 | NO_PERSON_INDICATED | yes |
| 0.39 | 1.00 | 0.574 | POSSIBLE_PERSON | yes |
| 0.45 | 1.00 | 0.616 | POSSIBLE_PERSON | yes |
| 0.00 | 1.00 | 0.300 | NO_PERSON_INDICATED | yes |
| 0.00 | 1.00 | 0.300 | NO_PERSON_INDICATED | yes |

Reduced-visibility profile, same scene: camera 0.00, radar 1.00, index 0.800, `POSSIBLE_PERSON`
after persistence. Profile was then restored to clear. Coverage was 1.0 (`FUSED_PROVISIONAL`)
throughout. Measured fusion tick: 11 distinct updates in 5 s (0.5 s interval).

Observations (one short session, not an evaluation):
- With a person present, camera detections were intermittent (0 to 0.45), so the clear-profile
  decision alternated between possible person and no person within seconds. The disagreement flag
  stayed set. Phase 5 should consider asymmetric persistence (fast on, slower off) or a longer hold,
  chosen on validation data rather than tuned on this session.
- Low camera scores may relate to distance/angle and the intermittent D2 wire; not separated here.

Fix after this check: a fusion result computed under the previous profile is now withdrawn
immediately after a profile change (it could previously be shown for up to one 0.5 s tick); covered
by an API test (40 tests pass). The running port 8000 backend picks this up at its next restart.

## Not yet established

- No accuracy, false-alert or delay figures; weights/thresholds are unselected.
- Camera D2 is intermittent: one live frame reverted to the green-capped magenta cast minutes after
  correct colour bars; a following sample of 20 frames was clean. Detection evidence is unreliable
  while this persists.
- In one live check a person close to the camera at a steep angle was visible but not detected
  (0 people); detector behaviour at close range/odd angles is unmeasured.
